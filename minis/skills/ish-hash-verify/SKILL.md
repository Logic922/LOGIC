# iSH 文件哈希与完整性校验

## 铁律（先看这个）

1. **GB 级文件不要在本机跑 `sha256sum`**。iSH 是 x86 指令逐条模拟，纯 CPU 活，50 MB 实测 2.38 s（≈21 MB/s）；6.5 GB 要 **约 5 分钟全程满载**，用户会感觉到发热、掉电快。先问"非算不可吗"。
2. **优先用大小判据**。下载完整性 90% 的问题（截断、漏段、Range 错位）都能被"字节数精确匹配"当场抓住，成本为 0。
3. **要哈希就用 `md5sum`**，它在本机快得多（见下表）。只有在需要和上游公布的 sha256 严格比对时才不得不跑 sha256，这时先告知用户预估耗时并征得同意。
4. **用 `delay` 而非 `sleep` 轮询**，长时间哈希不要用一条 shell 命令干等。

## 速度实测（2026-10-24，iSH Alpine aarch64，50 MB 文件）

| 命令 | 耗时 | 折算 | 6.46 GB 预计 | 说明 |
|---|---|---|---|---|
| `sha256sum` | 2.38 s | 21 MB/s（热缓存） | **≈9 分钟** | 最慢，别用于大文件；冷盘实测 87 s/GB |
| `cksum`（CRC32） | 0.43 s | 116 MB/s | ≈56 秒 | 只防随机损坏，不防恶意篡改 |
| `md5sum` | 0.10 s | 500 MB/s | ≈13 秒 | 首选；该数字为 page cache 命中下的 CPU 上限，冷盘读取会更慢 |

**真实大文件实测（2026-10-24，6.46 GB safetensors，模型下载后整文件校验）**：`sha256sum` 用了 **9 分 22 秒**，折 **87 秒/GB（≈11.8 MB/s）** —— 比上表的 50 MB 微基准慢约一倍，因为微基准读的是 page cache，真实文件要走磁盘。按 87 秒/GB 做预估。

未实测：多进程分块并行 md5（不要为了这点速度去试，SHA/MD5 是顺序链，只有分段独立校验才能并行）。

## 决策流程

```
要校验什么？
├─ 只是"下载有没有下完/下全"  → 大小判据（第 1 节），不哈希
├─ 有上游公布的 md5           → 整文件 md5sum（第 3 节）
├─ 有上游公布的 sha256        → 先算大小确认；确实要算 → 告知耗时，用 4 路并行 + 分段
├─ 只想确认没截断/错位        → 抽样哈希（第 2 节），秒级
└─ 必须原生速度              → iOS 快捷指令的 MD5/SHA256 动作（第 4 节）
```

## 1. 大小判据（首选，零成本）

```sh
stat -c %s <file>          # 实际字节数
```

与预期值**逐字节相等**才算通过。分段下载（多路 `curl -r` / aria2）要额外核对每段长度：

```sh
# 16 段各 433627543 字节，最后一段 433627537，总计 6938040682
ls -l parts/ | awk 'NR>1{print $9, $5}'
```

`--continue` 与 `-r` 组合出错时，症状就是某段字节数不等于区间长度，比哈希更早暴露问题。

## 2. 抽样哈希（几秒出结果）

只算头 / 中 / 尾各 4 MiB：

```sh
SZ=$(stat -c %s f.bin)
head -c 4194304 f.bin | md5sum
dd if=f.bin bs=1M skip=$((SZ/2/1048576)) count=4 2>/dev/null | md5sum
tail -c 4194304 f.bin | md5sum
```

能抓住截断、错位、尾部没 flush。抓不住"中间被篡改"——直链下载不需要担心这个。

## 3. 整文件哈希

```sh
md5sum f.bin                      # 6.5 GB 约 13 秒（热缓存），含读盘更久
sha256sum f.bin                   # ⚠ 6.5 GB 约 5 分钟满载，先征得用户同意
```

耗时预估公式：`秒 ≈ 大小(GB) × 87`（sha256，实测值）/ `× 2`（md5）。

并行分块（仅当能拿到分段校验值才有意义）：`md5sum` 单进程已经打满，别盲目开多进程。

## 4. 绕开模拟层

iOS「快捷指令」有原生 **MD5 / SHA256** 动作，走 ARM 原生代码、接近磁盘带宽，6.5 GB 十几秒完成。需要给用户时，描述步骤：`获取文件` → `计算 MD5` → `显示结果`，不要尝试在 iSH 里模拟。

## 5. 脚本

```sh
/var/minis/skills/ish-hash-verify/scripts/verify.sh <文件> [选项]

  --size N      期望字节数，精确比对
  --md5 HEX     期望 md5（隐含整文件 md5）
  --sample      只抽样（头/中/尾各 4 MiB），秒级
  --full        整文件 md5，输出耗时预估
  默认          只报大小
```

示例：

```sh
verify.sh /var/minis/shared/model.safetensors --size 6938040682 --sample
```

## 常见坑

- `time` 的输出走 stderr，与命令输出顺序会交错，脚本里解析要用 `{ time cmd; } 2>&1`。
- 校验过程中别用 `&` 起一堆后台任务：模拟层单核跑满，只会更烫、更慢。
- 先把文件 `sync` 或确认写入结束再校验，正在写的文件哈希结果无意义。
- `git-lfs`、`git add` 大文件同样慢，本质还是模拟层；能在宿主侧完成的就别放进来。
