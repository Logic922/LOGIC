# 精确编辑（Precise Code Edit）

单文件大工程里，最贵的 bug 不是设计错，而是**编辑器械伤**：切多一行留下残骸（白屏），
切少一行静默没改（以为修好了），删了函数忘了删引用（导出整块变 `undefined`，页面却照常显示）。

本技能的规则是这些事故的沉淀。改动越"小、局部、看起来不会错"，越要照做。

## 铁律

1. **改前先读**。用 `file_read` 看当前内容再写 `old_string`，不要凭记忆或凭上一轮看到的版本。
2. **锚点必须唯一**。下手前 `grep -c` 数一遍；不唯一就加长锚点（带上前后各一行）。
3. **禁止用 find/index 手工切片做区域替换**。需要删一段就用
   `safe_replace.py --region-start ... --region-end ...`，由脚本断言两个锚点各出现恰好 1 次。
4. **一次只做一件事**。"行为不变的重构"和"修改行为"分两次做、分别验证。
   混在一起时，出问题无法判断是哪一类造成的。
5. **禁止"我没有改它"**。任何替换都要能给出替换次数；0 次命中必须报错，不能沉默通过。
6. **不许 no-op**。`old == new`、或改了却没有任何可观测行为变化 —— 那不是修复，是表演。
   脚本会直接拒绝。
7. **不变量优先**。改前先记下"必须保持不变的东西"（缓存键、常量值、函数个数、音符数…），
   改后逐条复算。重构的验收标准是"这些数一个都没变"。

## 改后立刻跑四级验证阶梯

| 级别 | 查什么 | 命令 |
|---|---|---|
| L0 语法 | 白屏类错误 | `node --check F.js` / `python3 -m py_compile F.py` |
| L1 悬空引用 | 导出表/导入清单引用了已删除的标识符 | `verify_edit.py F --exports` |
| L2 清单 diff | 顶层标识符多了/少了 | `verify_edit.py F --inventory --baseline base.json` |
| L3 行为 | 真实输入上的输出没变/变成预期的值 | 跑项目自带测试；没有就现写一个最小断言脚本 |
| L4 边界 | 畸形/空/超大输入不崩 | 造一条畸形输入实跑 |

**L1 是最容易被跳过、后果最严重的一级**：删掉一个顶层函数后，若文件末尾的
`window.X = {...}` 还引用它，整个导出赋值会抛 `ReferenceError`，
`window.X` 变成 `undefined` —— 页面照常显示、播放列表正常、语法检查通过，
只有 `typeof window.X` 才暴露。**凡删除/重命名任何顶层标识符，必跑 L1。**

## 工具

```bash
S=/var/minis/skills/precise-code-edit/scripts

# 改前：存一份顶层标识符基线（用于 L2）
python3 $S/verify_edit.py app.js --save-baseline /tmp/inv_before.json

# 替换（--old-file/--new-file 最稳，避开 shell 引号地狱；先 --dry-run 预演）
python3 $S/safe_replace.py app.js --old-file /tmp/old.txt --new-file /tmp/new.txt --count 1
python3 $S/safe_replace.py app.js --old 'foo(vk)' --new 'Math.min(1, vk*8)' --dry-run

# 删除一段代码：两个锚点各须唯一
python3 $S/safe_replace.py app.js --region-start 'function trimIDB(){' \
        --region-end '  });\n}' --new-file /tmp/empty.txt

# 改后：一条命令跑全部自检
python3 $S/verify_edit.py app.js --all --baseline /tmp/inv_before.json
```

`safe_replace.py` 成功时输出 `replacements / new_count_after / lines_added / lines_removed / backup`，
可直接贴进对话作为"我确实只改了这几行"的证据；断言失败时**文件不会被修改**（退出码 1）。

### 工具局限（已知，务必遵守）

- **`--unused` 只是启发式提示，不是结论。** 判据是"该标识符在**原文**中出现次数 ≤ 1"，
  方向刻意保守（宁可漏报也不误报）。删除任何一条前必须人工确认 ——
  同名局部变量、字符串里的引用都会干扰计数。
- **`--exports` / `--unused` 都依赖文本剥离层**（把字符串/正则/注释替换成空格）。
  剥离层一旦出错，错的方向是**静默漏报**。因此每次输出里都带 `strip_ratio`
  （剥离后剩余的非空白字符占比，正常 JS > 0.3）；低于 0.15 时代码会自己报
  `stripper-suspicious` 并把本次结论标记为不可信。
- **通则：工具的结论也要能自证。** 任何"分析类"脚本都应该输出一个能被外部检验的
  健全性指标（比率、计数、样本数），否则它出错时你无从察觉 —— 详见事故档案第 8 条。

## 声称"修好了"的举证责任

- **必须实测改动前的值**，不许从代码推断出"它以前是错的"再假定现在变了。
  曾经的教训：把一个恒定取默认值的表达式改成"看起来更正确"的写法，其实是 no-op，
  而"实测 170/142"是拿想象中的修前值与真值对比 —— 等于自己骗自己。
- **无法验证的要明说**。例如音频/渲染/原生弹窗行为在无头环境不可测时，
  只能从"相关函数逐字符未变 + 常量未变 + 缓存键未变"这条推理链给出**弱**结论，
  并且明确标注"未实测"。不要把推理链包装成实测。
- **验证脚本本身也会骗人**：用 `indexOf(锚点)` 做切片前先断言锚点存在（`-1` 会切出空串，
  静默误报"没落地"）；用自己的备份文件做函数级 diff 时，确认备份确实来自改动前。

## 收尾

- 验证通过后删除临时夹具；备份（`*.bak.*`）在验证通过前保留，通过后再清理。
- 用 `--dry-run` 探索；确认无误再真写。
- 详细事故档案见 `references/failure-catalog.md` —— 当你想"这次改动很简单不用检查"时读它。
