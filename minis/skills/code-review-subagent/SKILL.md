# 代码审查（子代理完整审查）

**核心前提：改代码的人不能自己签发"没问题"。** 自己写的自检必然带盲区 ——
自检只能证明"我检查了我想到的东西"，而 bug 恰恰住在没想到的那一块。
所以每次非平凡改动之后，交给一个**看不到对话历史、只听 brief** 的子代理，
让它通读整份代码并**用工具自证**，然后主代理独立核实它说的每一条。

## 触发时机

必须审查：改了控制流/状态机、删除或重命名了标识符、批量替换 >10 处、
动了不可测的脆弱路径（音频、渲染、IndexedDB、原生桥）、上一轮刚修过的东西。
可以不审：改注释、改文案、加一行日志。

## 执行顺序（一轮）

```
0. 主代理自检        → precise-code-edit 技能：语法/悬空引用/清单 diff（先把低级错误清掉，
                       否则子代理的时间全花在你自己的机械损伤上）
1. 派子代理（只读）  → 用 references/review_brief.md 的模板，逐项填满再发出
2. 逐条独立核实      → 自己复现每一条；能复现的进修复清单，不能复现的记下理由
3. 修复 + 再自检      → 修复本身也走精确编辑技能
4. 再派子代理复审     → 必做。禁止用"我已经修好了"代替复审
5. 收敛判定          → 直到新一轮无**新实质问题**为止；每轮 bug 数应递减
```

第 4 步不可省：**修改会引入新 bug**，这是历史里反复出现的事（修一处、撞出另一处）。
复审 brief 里要专门写一句：*"重点检查上一轮修复是否引入了新的回归。"*

## 派子代理的 brief 必须包含（缺一项就会得到无用的审查）

1. **文件绝对路径 + 行数 + 语言**，以及项目硬约束（例："单文件零依赖，不得拆分成多个文件"；
   "不得改动音频数据路径"；"保持 README 承诺的行为"）。
2. **"通读整份文件"** 的明确指令，并给出可行的读法（分段读、每段读完输出该段结论），
   否则子代理只看 diff 就下结论。
3. **允许并鼓励动手验证**：跑 `node --check`、`python3 .../verify_edit.py F --all`、
   `grep -c` 计数、写最小复现脚本、跑项目自带测试。
4. **只读，禁止修改任何文件** —— 明文写出来。否则它会顺手"帮你重构"，
   把审查变成未经授权的改动（历史上真实发生过：子代理把守则里列为禁区的比较表达式改掉了）。
5. **输出格式**：一条一个问题，字段固定为
   `位置(函数/行号) · 现象 · 触发条件 · 证据(命令+输出) · 严重度(致命/功能/边界/风格) ·
   置信度(已复现/推测) · 建议修法`。要求**把风格问题单独归类**，不要混进 bug 列表凑数。
6. **要求它列出"我没验证的部分"**，以及它认为自己的哪些结论最可能是误报。
7. 若是复审轮：附上上一轮的 bug 清单和你的修复摘要，要求逐条判定
   `已修复 / 未修复 / 部分修复 / 修复引入新问题`。

模板见 `references/review_brief.md`，直接复制填占位符。

## 主代理的核实义务（不能省）

- **不采信子代理的自述**。它说"我已验证 X"，你要自己再算一遍。
- 对"行为不变的重构"，做**函数级 diff**（拿改动前的备份逐函数对比），
  并复算一小组硬数字（顶层函数个数、真实样本的输出计数、缓存键/序列化键）。
- 对"性能优化"，确认优化后的结果与优化前**逐字节/逐样本一致**。
- 对"无法在本环境验证"的结论（音频听感、原生弹窗、后台行为），
  明确标注为**推理结论**并写清推理链的每一环，不要包装成实测。
- 核实结果要能贴出数字（`19/19 PASS`、`258/3122/1909`、`函数 75→75`），
  而不是"我又看了一遍，没问题"。

## 反模式

- 子代理只说"整体看起来没问题" → brief 里没给足约束，重发。
- 子代理报了大量风格问题掩盖真 bug → 严重度分级，风格单列。
- 子代理越界改代码 → 立刻 `git diff`/备份比对回滚，并在下轮 brief 里加强只读约束。
- 只审 diff 不审全文 → 上下文相关的 bug（跨函数状态、缓存键、导出表）永远抓不到。
- 一轮就宣布"代码完美" → 收敛判据是**连续复审无新实质问题**，不是"修完了"。

## 成本与并行

一个文件一轮一个子代理（`subagent_task`，`wait=false`，结果回来后再动手）。
文件大、问题多时可分段并行（按功能区拆 2–3 份），但**同一轮不要派两个代理审同一段**
—— 重叠审查会互相矛盾，浪费预算。
